# Used as a pip constraints file (-c) in the Dockerfile: it doesn't add packages, it only fixes
# the version of any package that gets installed. This keeps the Python 3.12 image identical
# to the 3.9 one apart from Python, the OS and the Jupyter tooling, so env_00_reference_sessions
# compares like with like.
#
# Generated from py39-freeze.txt, keeping only `name==version` lines and leaving out:
#   - the Jupyter stack (jupyterlab 3.6 doesn't fit the new base image; it moves to 4.x)
#   - packages installed from git, which the Dockerfile pins to their baseline commits instead
# Every version here resolved for Linux + Python 3.12 on 2026-09-24.
#
# To upgrade a package deliberately, change or delete its line here.
#
# Bumped from the baseline because the 3.9 version has no Linux wheel for Python 3.12 and its
# C extension fails to compile there (2026-09-25; found when PyYAML 6.0 broke the first build).
# Each is the smallest bump that has a wheel, and none is used in numerical code:
#   PyYAML 6.0 -> 6.0.1, pyzmq 25.0.0 -> 25.1.1, MarkupSafe 2.1.2 -> 2.1.3
# Still built from source on 3.12:
#   - pure Python, build fine: asciitree, moviepy, open-ephys-python-tools, zmq
#   - pymongo 4.3.3: can't be bumped, because aind-data-access-api[docdb] (latest, 1.10.0) pins it
#     exactly. Its C extensions are optional; if they fail to compile, pymongo installs pure
#     Python and works (just slower).
#   - wavpack-numcodecs 0.1.5: C code, compiles against build-essential as it already does on 3.9.
#
# Notebook-kernel fix (2026-09-25). Kernels hung at startup when a notebook was first run from
# VS Code (eph_01, kin_07). Two tooling changes, neither used in analysis code:
#   - debugpy 1.6.6 -> 1.8.20: 1.6.6 predates Python 3.12 support (added in 1.8.x); it only
#     installed because it ships a generic py2.py3 wheel. ipykernel loads it at kernel start.
#   - ipykernel held at 6.29.5 (last 6.x; the 3.9 image had 6.21.3) instead of floating to 7.x,
#     which changed kernel start/interrupt/restart handling.
